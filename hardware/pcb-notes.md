# Bench Breathe A0 PCB notes

**Evidence class:** static layout + DRC + autoroute log. No bench, radio,
thermal, or field measurements were performed. The board is A0
first-silicon intent; all claims below are geometry and design-rule facts
reproducible from the committed sources.

## Inputs and reproduction

Electrical truth comes only from the A0 schematic netlist
(`bench-breathe.kicad_sch`, regenerated by `generate_schematic.py`) — pin
maps are never re-typed here. From the repository root:

```bash
kicad-cli sch export netlist hardware/kicad/bench-breathe.kicad_sch -o /tmp/bb-netlist.net
python3 hardware/kicad/scripts/netlist_json.py /tmp/bb-netlist.net /tmp/bb-netlist.json
# pcbnew API build (inside the KiCad 9 image used by the kicad-cli shim):
docker run --rm -u $(id -u):$(id -g) -e HOME=/tmp/kicad-home \
  -v "$PWD":/hw -v /tmp:/tmp parts-tally-kicad:9-arm64 \
  sh -c 'mkdir -p $HOME/.config/kicad/9.0; cp /usr/share/kicad/template/fp-lib-table $HOME/.config/kicad/9.0/; \
  python3 /hw/hardware/kicad/scripts/build_pcb.py /tmp/bb-netlist.json /hw/hardware/kicad/bench-breathe.kicad_pcb'
# Specctra route loop (FreeRouter 2.1.0 on JDK 21, headless; each pass
# re-exports the DSN from the just-imported board):
#   scripts/export_dsn.py board.kicad_pcb passN.dsn
#   java -Djava.awt.headless=true -jar freerouting-2.1.0.jar -de passN.dsn -do passN.ses -mp 20 -gui.enabled=false
#   scripts/import_ses.py board.kicad_pcb passN.ses
#   scripts/refill_zones.py board.kicad_pcb        # stored fill is stale after import
#   scripts/stitch_pour_islands.py board.kicad_pcb # GND pour islands -> stitching vias (bounded, idempotent)
#   scripts/fix_starved_pads.py board.kicad_pcb REF:PAD ...
#   scripts/close_stubs.py board.kicad_pcb passN-drc.json
kicad-cli pcb drc hardware/kicad/bench-breathe.kicad_pcb --severity-error --severity-warning \
  --format json --output hardware/kicad/reports/pcb-drc-final.json
```

`hardware/kicad/bench-breathe.kicad_pro` carries the real design rules and
net classes (KiCad 9 reads DRC constraints from the project file, not from
API-side board settings): default 0.2 mm clearance/track, Power class 0.4 mm
(VBUS, VBUS_FUSED, SW_NODE, PM_5V, +3V3), USB class 0.25 mm between the
connector and the module. See `scripts/make_project_settings.py` for the
rationale of the 0.2 mm min through-drill (manufacturer ESP32 module
heat-sink vias and WSON thermal-via land pattern ship 0.2 mm drills).

## Board concept (KiCad coordinates, +Y toward the bottom edge)

65 × 75 mm, two copper layers, four M3 corner holes at (±3.5) insets.
Functional zones:

- **USB entry / protection (bottom edge):** J1 USB-C (top-mounted
  horizontal, opening facing the y=75 edge, two press-fit anchoring slots
  with copper-free rings), TPD4E05 ESD array U6 at the escape, CC1/CC2 5.1 kΩ
  Rd resistors, PPTC F1 + SMBJ5.0A TVS D1 on VBUS, then 0 Ω DM/DP config
  links (R11/R12).
- **3.3 V buck (bottom-left):** TPS62162 U5 with input bulk C1, 2.2 µH L1
  and 22 µF C2 in a tight power loop; PG pull-up R3 beside it.
- **PM rail (bottom-right):** TPS22919 load switch U7 + bulk C10 feeding the
  JST PH SPS30 harness header J2 at the right edge (53.5, 50).
- **Controller (top-center):** ESP32-C3-WROOM-02 U1 at (32.5, 20.5) with the
  antenna arm oriented toward the **top edge** and its copper-free keepout
  rule area (18.25–46.75 × 2.15–13.65 mm, both layers, priority 1) fully
  inside the board outline; EN/BOOT/3V3 passives at its corners; 1×06 debug
  header J3 flat on the left side (14.4, 30).
- **Sensors (right-center):** SGP40 U3 + SHT40 U4 with local bypass parts on
  a quiet island away from the buck loop; I2C pull-ups R5/R6 sit between
  master and slaves. SHT40's open cavity (NoCentralPad footprint) keeps the
  sensing opening free of paste/fill.
- **User interface (left/right middle):** button SW1 + pull-up/debounce at
  x=7.5 (reachable from a desk front-left) and status LED D2 + R9 at the
  right middle, away from the sensor island so hand heat does not bias SHT40.

## Grounding strategy (AC-3)

Solid GND pour on **both** layers (verified filled: F.Cu ≈ 3.14 × 10³ mm²,
B.Cu ≈ 3.70 × 10³ mm² after the final post-route refill), thermal relief to
pads, with full connect set on the edge/shell pads that starve thermal relief (J1 A12/B1,
U6 pad 8, J3 pad 2, U3 EP). Rationale:

- Two solid layers give every signal a same-or-adjacent-layer return; the
  buck input loop (C1→U5→L1→C2) is kept small at the bottom-left corner so
  its di/dt does not ride the sensor return.
- The SGP40/SHT40 island routes I2C and VDD over unbroken pour; sensor VDD
  uses the datasheet RC (10 Ω + 100 nF). The A0 plan is one ground domain —
  separation is by layout, not by a split plane.
- SPS30 UART runs from the module to the right-edge J2 over the pour. The
  SPS30 housing is chassis-tied internally per Sensirion, so J2 carries no
  separate chassis path.
- USB DM/DP run short through the ESD array and 0 Ω links without layer
  transitions where the router allowed.

## Keepouts and documented exceptions (AC-4)

- **Antenna keepout:** priority-1 rule area over the module antenna arm
  forbids copper pour on both layers; `SetDoNotAllow*` flags allow the
  module's own pads/vias inside the rectangle. The keepout is inside the
  board outline; the top-edge clearance is what matters for radio coupling.
- **Mounting-hole (r=2.7 mm) and USB press-fit-tab copper-free rings** are
  priority-1 rule areas that carve the pour but explicitly allow their own
  hole/tabs (default rule areas would flag the hole's own pad).
- **SHT40 cavity:** project footprint has no central pad and no paste; the
  validator asserts the footprint choice at schematic level.

## Testability and fab-readiness notes (AC-5)

- 19 named test points, one pad each: TP1 VBUS, TP2 VBUS_FUSED, TP3 +3V3,
  TP4 GND, TP5 PM_5V, TP6 REG_PG, TP7 EN, TP8 BOOT_GPIO9, TP9 I2C_SDA,
  TP10 I2C_SCL, TP11 USB_DP, TP12 USB_DM, TP13 CC1_SENSE, TP14 CC2_SENSE,
  TP15 PM_ENABLE, TP16 USER_BUTTON_N, TP17 PM_UART_RX, TP18 PM_UART_TX,
  TP19 SGP_VDD. TP11/TP12 sit on the module side of the 0 Ω links so the
  host-side pair can be isolated at the bench.
- Mounting: 4 × M3 at (3.5, 3.5) … (61.5, 71.5) with copper-free rings;
  J1 press-fit tabs are anchored by two plated slots plus soldered shell
  pads.
- Connector orientation: J1 opening faces the bottom edge; J2 (SPS30
  harness) exits the right edge; J3 debug header is horizontal on the left
  so a ribbon/Tag-Connect exits sideways.
- Polarity marks: all polarized parts (D1, D2, C1–C3, C10, U5, U7, J1, J2)
  keep silkscreen polarity graphics; TP/SW references stay visible (shrunk
  0.8 mm/0.15 mm stroke text) because test-point identity is part of the
  testability criteria. Dense R/C/D references are hidden post-route —
  values and courtyards remain on Fab layers.

## Residuals carried into A1 / issue #8 (AC-4 honesty)

**Final DRC state** (`reports/pcb-drc-final.json`, KiCad 9.0.9, severities
error+warning, evidence class = static geometry check): **0 violations**;
17 `unconnected_items`, of which 2 are `Zone [/GND] <-> Zone [/GND]` pairs
anchored at the pour outline's (0.3, 0.3) corner — pseudo-ratsnest artifacts
of the filled polygon, not routable copper — leaving **15 open ratsnest
edges** as the explicit pre-fab blocker. Per-pair collision dumps for every
one of the 15 are in `reports/ratsnest-diagnosis-final.txt`. Deterministic
closure attempts (`close_stubs.py`, straight + both L topologies, 0.2 mm
clearance capsule + keepout collision): `fixed=0 left=15 skipped=2` — every
remaining pair is fenced by foreign copper at exactly netclass clearance
(pitfall-30 physics gate, not router failure). FreeRouter itself exited
naturally at plateau pass #999 (15 unrouted — same 15 edges;
`reports/freerouter-pass5-summary.txt`).

Blocker classes for A1, each with its named fix (15 = 6 + 3 + 3 + 3):

- **USB-C/TPD4E05 fanout congestion (CC1_SENSE ×1, CC2_SENSE ×3,
  VBUS ×2):** the TPD4E05 DFN-10 escape and the
  USB-C mid-mount pads leave corridors narrower than track+2×clearance in
  the 0.25 mm USB class; J1 B4↔B9 VBUS bonding and the CC lines cross the
  A5/A6/B5/B6 pad rows. Fix: local `scan_fanout` netclass (0.13 mm/0.13
  mm) for CC*/VBUS-bond segments plus a 0.35 mm pad-pair nudge of
  U6, or fan the CC sense lines out on B.Cu immediately under U6.
- **SHT40 cavity keepout corridor (I2C_SDA ×1, I2C_SCL ×1, +3V3 ×1,
  all landing on U4):** straight closures pass the pure-collision check
  but cross the SHT4x sensing-cavity `tracks not_allowed` rule area. Fix:
  route the last hop inside the footprint-embedded fanout corridors the
  datasheet allows, or re-anchor the cavity keepout polygon with the
  pad-pair gaps open.
- **Module-row edge stubs (I2C_SCL to TP10 ×1, REG_PG to U1.15 ×1,
  USER_BUTTON_N to U1.10 ×1):** the 26.37 mm +3V3 bus rail and the
  module's own USB_DM/BOOT pads sit at exactly clearance. Fix: move the
  bus rail one grid notch (0.25 mm) east at re-place and re-anchor TP9/
  TP10 outside the pad-row shadow.
- **Buck/power-loop congestion (SW_NODE ×1, VBUS_FUSED ×2):** the 0.4 mm
  Power class cannot thread the WSON-8 pad row or the R12/C12/U7 escape.
  Fix: Power-class width exception (0.2 mm for the last 1 mm) or nudge
  L1/TP2 so their stubs leave the pad shadow; re-place TP2 beside the F1
  output stub.

Until these 15 close (A1 nudge or manual fanout), **the board is NOT fab
release** — it is an A0 evidence board for placement/DRC/geometry
validation only.
- USB DM/DP are not length-tuned or impedance-controlled (≈ 0.25 mm/0.2 mm
  on generic 1.6 mm 2-layer ≈ 95–110 Ω uncontrolled), acceptable for the
  ESP32-C3 full-speed (12 Mbps) USB used for bring-up and the companion
  app. **No USB High-Speed or compliance claim is made.**
- Antenna coupling, radio range, and RF certification are bench/field
  evidence (issue #8); static checks cannot evaluate them.
